## 三、🟡 警告问题

### 🟡-1 `L2` / `L58` / `L97` `watch`、`computed` 未显式 import

**问题**
```js
import {getCurrentInstance, onMounted, reactive} from "vue";
```
但 L58 使用了 `computed`、L97 使用了 `watch`。运行时依赖 `unplugin-auto-import` 兜底（`vite/plugins/auto-import.js` 配置了 `imports: ['vue']`），**不会报错**；但该配置 `dts: false`，不生成类型声明，IDE / vue-tsc 无法解析：

> 未解析的函数或方法 watch()  — 当前编辑器诊断
> 未解析的函数或方法 computed()

本仓库其余 19+ 个业务页面全部显式 import（如 `collectionBusiness/index.vue:2`、`paymentBusiness/registrationSocialSecurityFund/index.vue:2`），本文件是唯一例外。一旦 auto-import 插件配置或文件位置变动（例如被抽成独立 `.js` 文件、或 include 规则调整），会直接变成运行时报错。

**修复建议**
```js
import {computed, getCurrentInstance, onMounted, reactive, watch} from "vue";
```

### 🟡-2 `L58-60` 按钮 `disabled` 用 `computed()`，与组件约定的函数形式不符

**代码**
```js
{ type: 'button', label: '生成收款单', btType: 'primary', disabled: computed(() => {
  return !tableInfo.sectionRows.length || !!tableInfo.sectionRows.find(it => it.createFlag == 1 || it.type != 2)
  }), ... },
```

**问题**
`NewPageFilter` 对按钮 `disabled` 的处理是（`src/components/NewPageFilter/index.vue:1990`）：

```js
function setBtnDisabled(btnDisabled) {
  if (typeof btnDisabled === 'string' || typeof btnDisabled === 'boolean') {
    return btnDisabled
  } else if (btnDisabled && typeof btnDisabled === 'function') {
    return btnDisabled()      // ← 组件约定：函数形式
  }
}
```

`computed()` 返回的是 ref **对象**，既不是 string/boolean 也不是 function，`setBtnDisabled` 会返回 `undefined`。

当前之所以“看起来正常”，是因为 `filterInfo` 是 `reactive`，模板取 `item.disabled` 时经过了 reactive 的对象属性取值，ref 被自动解包（这是隐式行为：`targetIsArray && isIntegerKey` 时才不解包，而这里是「对象属性」而非「数组下标」）。这层隐式解包一旦被破坏就会静默失效——例如有人对 `btnList` 做了 `cloneDeep` / `JSON` 处理，ref 会丢失，`setBtnDisabled` 返回 `undefined` → **按钮永远可点**。

同时，同页 L97-100 的「删除」按钮又用了 `watch` 改 `disabled` 的写法，同一个 `btnList` 里两种风格并存，维护成本高。

**修复建议**（推荐：统一为组件约定的函数形式，删除 L97-100 的 watch）
```js
{ type: 'button', label: '生成收款单', btType: 'primary',
  disabled: () => !tableInfo.sectionRows.length || !!tableInfo.sectionRows.find(it => it.createFlag == 1 || it.type != 2),
  show: proxy.$permission(`${PERMISSION_CODE}:build`), event: () => buildData(), },

{ type: 'button', label: '删除', btType: 'primary',
  disabled: () => !tableInfo.sectionRows.length,
  show: proxy.$permission(`${PERMISSION_CODE}:delete`), event: () => deleteData(), },
```

### 🟡-4 `L46` `select-model` 的 `event: getList` 查询到的是「变更前」的值

**代码**
```js
{ label: '收付款类型', value: 'type', type: 'select-model', code: 'funds_payment_type', event: getList },
```

**问题（时序）**

### 🟡-5 `L79` 「下载日期」formatter 对空值处理错误

**代码**
```js
{ label: '下载人', value: 'updateUserName' },
{ label: '下载日期', value: 'updateTime', align: 'center', formatter: (val) => moment(val.updateTime).format('YYYY-MM-DD') },
```

**问题**
`updateTime` 是「下载日期」，未下载过的行该字段大概率为空。`moment` 对 `undefined` 的语义是**取当前时间**（等价于 `moment()`），对 `null` 则返回 Invalid date：

- 字段缺失（`undefined`）→ 列表显示**今天的日期**，属于会误导业务判断的错误数据；
- 字段为 `null` → 显示 `Invalid date`。

`tradeTime`（L70，交易日期）一般有值，风险较低；但「下载日期」必须判空。

**修复建议**
```js
{ label: '下载日期', value: 'updateTime', align: 'center',
  formatter: (val) => (val.updateTime ? moment(val.updateTime).format('YYYY-MM-DD') : '-') },
```

### 🟡-6 `L117-123` `reset()` 会弹出校验告警、且列表不刷新

**代码**
```js
function reset() {
  filterInfo.query = {
    tradeTimeEqAndGre: defaultDate1,
    tradeTimeEqAndLes: defaultDate2,
  }
  getList()
}
```

**问题**
重置直接把 `filterInfo.query` 换成只含两个日期的对象，**丢掉了 `bankAccountId` / `bankAccountName`**；紧接着调用的 `getList()` 里 `requiredPageFilter`（L107）发现必填的「银行账户」为空，于是：

1. 弹出 `请填写银行账户` 警告；
2. 直接 `return`，`tableInfo.refresh` 未被更新 → **列表既不刷新、也仍显示重置前的旧数据**。

即「重置」按钮的实际效果是：清空账户 + 一个警告框，数据没有任何变化。

（同类型页面 `accountDetailStatement/index.vue:128-136` 存在同样写法，属历史模式；但本页银行账户是必填项且清空后必须重新选择，用户会明确感知到“重置没用”。）

**修复建议**（任选其一）
```js
// 方案 A：重置时保留账户，只重置日期与其他条件（推荐）
function reset() {
  filterInfo.query.tradeTimeEqAndGre = defaultDate1
  filterInfo.query.tradeTimeEqAndLes = defaultDate2
  filterInfo.query.type = undefined
  filterInfo.query.tradeBankNameLike = undefined
  filterInfo.query.remarkLike = undefined
  getList()
}
```
```js
// 方案 B：保留清空账户的行为，但给出明确提示并同步清空表格
function reset() {
  filterInfo.query = { tradeTimeEqAndGre: defaultDate1, tradeTimeEqAndLes: defaultDate2 }
  filterInfo.copyQuery = {}
  tableInfo.data = []
  proxy.$message.warning('请重新选择银行账户')
}
```

### 🔵-2 `L200` `type="input"` 不是合法的 `el-input` type

```html
<el-input ... type="input" :required="true" :disabled="true" placeholder="请选择银行账户">
```

`el-input` 的 `type` 只支持 `text` / `textarea` / `password` / `number` 等原生值，`input` 不在其中（会作为无效属性透传到原生 `<input type="input">`）；`required` 也不是 `el-input` 的 prop，会原样透传到原生 input。

均不影响功能，属项目既有写法（`accountDetailStatement/index.vue:174,191` 一致），建议清理为 `type="text"` 并移除 `:required`，或直接不写。

## 五、正面反馈

- **接口层规范**：`src/api/business/accountTransactionDetails.js` 四个接口全部声明了 `btnCode`（list / download / delete / build / export），未绕过 `request` 实例，符合项目约定。
- **敏感操作二次确认**：删除前有 `proxy.$confirm('删除后将改变数据,是否继续?')`（L146-151），符合安全要求；`deleteData()` 内部对空选中做了 `ids.length === 0` 兜底。
- **数据隔离**：`getList()` 里 `copyQuery` 用 `cloneDeep` 并显式把展示用的 `bankAccountName` 置为 `undefined`（L109-112），避免把名称类字段发给后端，与 `collectionBusiness` 等页面的处理一致。
- **导出/下载走统一 Hook**：使用 `useUpload(API)`、`useDownloadLog('bmp_detail')`，未自行拼装 axios，与 `accountBalance`/`ebankReceipt` 的 `bmp_*` 命名保持一致。
- **页面样式分离**：`<style scoped lang="scss">` 为空，样式全部复用全局类（`app-container` / `layui-card` / `filter-wrapper`），无样式污染。
- **文件规模**：248 行，未超过 300 行阈值；`defineOptions({ name: PERMISSION_CODE })` 显式声明组件名，有利于 keep-alive 与 `$router.currentRoute.name` 判断。
